- A service-only Store access switch defaults **disabled**. The database migration is prepared, not applied. Eleven local endpoint adapters now import the new context helper; production consumers are unchanged.

Initial administration remains Internal Administrator-controlled; the prepared Owner path is not exposed.
- Contractor expiration validation uses server-owned `app_metadata` returned by a fresh authenticated Auth lookup and the New York calendar day, never editable `user_metadata`. The database service is not granted direct `auth.users` access. RPC caller identity must be supplied by the server after authentication, not by request JSON.

## Session races repaired in local source

The executable tests load the actual `portalFetch`, `refreshSession` and refresh-scheduling methods from the portal HTML; they do not reimplement the behavior. Before the fixes, four cases failed: a completed refresh for an old workspace expired the current workspace; an old identity's refresh overwrote a newer sign-in; an older flight could interfere with a newer session's refresh; and reauthentication with the same email/workspace did not invalidate an older request.

The source now rechecks context before expiring a session, binds refresh writes to the identity/session generation including queued state updates, and clears only its own refresh flight. Timer error handling is similarly identity-bound. Normal token rotation still works across a workspace switch for the same person; concurrent callers share one refresh request. Failed refresh for the current session still expires it; HTTP 403 does not trigger refresh.

This follows the bug-diagnosis workflow: deterministic failing regressions, one-variable checks, then fixes and repeat execution. No production instrumentation was added.

## Endpoint migration follow-up

The local adapters for `portal-admin`, `canix-catalog`, `portal-pricing`, `portal-intake`, `portal-orders`, `portal-order-policy`, `quickbooks-financials`, `portal-claims`, `portal-notifications`, `portal-assets` and `portal-retailers` now require a selected membership after Auth verifies the caller. Accepted retries verify the original payload fingerprint without demanding that the original stock or price remain unchanged. Changed-payload retries fail. Buyer approval is denied; controlled Owner approval cannot approve the Owner's own order. Store transitions do not enqueue a Monday handoff.

Store pricing proposals and receiving-claim changes use the same transactional boundary. Existing Internal workflows remain separate. External catalog/order projections use positive field allowlists and omit costs, ownership, package tags, internal notes and source queue identifiers. Budtender receives education only. Exact sellable quantities remain `null` in the catalog projection until the quantity integration acceptance is complete; unknown quantity is not zero.

Legacy Store invitation/global-profile update actions are held; the new scoped revocation action is Internal Administrator-only. Store template sends, invoice notices and retries of stored Store emails are held before recipient lookup, quota consumption or provider calls. New document classes, exports and file-sharing policies are not enabled. Existing Brand/Internal consumers outside the eleven adapted endpoints still require regression and selected-workspace review before a coordinated release.

Same-origin tabs now receive a token-free sign-out signal for the same identity. They clear local state without repeating server logout. Signals for another identity, stale signals and malformed messages are ignored. Tabs keep independent workspace selection; this is not a cross-tab token-sharing or refresh-lock implementation.
